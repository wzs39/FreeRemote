# 管理员模式说明（run-admin.bat）

## 现象

手机能控制普通窗口，但打开**任务管理器**（或右键"以管理员身份运行"的程序）后：
鼠标移得过去、点击和键盘没反应 —— 好像"所有操作都失灵"。

## 原因：Windows UIPI（用户界面特权隔离）

当目标窗口的权限等级**高于**注入输入的进程时，模拟的鼠标/键盘事件会被系统**静默丢弃**：

- 任务管理器默认以管理员运行
- UAC 弹窗（安全桌面）级别更高，任何普通进程都无法注入
- 某些游戏/反作弊程序也会拦截模拟输入

这不是 FreeRemote 的 bug，是 Windows 的安全机制。

## 解决：以管理员身份运行 FreeRemote

双击 **`run-admin.bat`**（会自动弹出 UAC 提权确认，点"是"）。

它的输入注入就能到达所有同级及以下的窗口，包括任务管理器。
内部仍然跑看门狗 `hot.py`（崩溃自动重启 + 热更新），功能不变。

### 建议日常用法

| 场景 | 用哪个 |
|---|---|
| 只控制普通程序 | `run.bat`（无需提权，够用） |
| 需要控制任务管理器/管理员程序 | `run-admin.bat` |
| 开机自启 | `install-autostart.bat`（普通权限；需要控制管理员窗口就用计划任务以最高权限注册，见下） |

### 自启 + 管理员权限（可选）

把自启任务改为"最高权限运行"：

```
schtasks /Change /TN FreeRemoteLAN /RL HIGHEST
```

（`FreeRemoteLAN` 是 install-autostart.bat 注册的任务名。修改后需管理员终端执行一次。）

## 另一个常见"全部失灵"：卡键

如果失灵的是**所有应用**（不只是管理员窗口），多半是电脑端 Ctrl/Alt/Shift/Win
被卡在按下的状态（手机断线/息屏时正按着）。本项目已做三层防护：

1. **断线自动释放**：电脑端检测到控制连接断开，立即释放全部修饰键
2. **重连自动同步**：手机重连成功后自动发一次释放指令
3. **手动一键自救**：手机工具栏新增 **「解锁键盘」** 按钮，点了立即释放并复位

## 边界（无法绕过）

UAC 确认弹窗所在的"安全桌面"仍然无法注入 —— 系统级保护，任何远程软件都一样。
可以先点「解锁键盘」清掉卡键，关掉弹窗后再继续操作。
